### 未实机验证意味着什么

上表标「仅离线 / 仅 QEMU」的 KMI，只保证：`.ko` 能编译、能通过完整性校验、
能在 QEMU GKI 或离线夹具里走完加载流程。**没有在对应 Android 版本的真机上跑过**，
因此不保证：

- 该内核的符号表与 `.ko` 的 116 个外部符号完全对齐（`susfs_insmod` 会打印 resolved 比例）
- 该内核的 `struct` 布局与 LKM 一致（不一致时通常表现为 `init_module failed: errno 14 (EFAULT)`）
- 该内核未被厂商开启强制模块签名 / `modules_disabled=1`

如果你在标「未验证」的 KMI 上跑通了，欢迎按 [反馈](./SUPPORT.md) 提交 `load.log`，
我们会把结果补进上表。

## 匹配顺序

1. 内核版本字符串带 `-androidXX-<kver>`：直接匹配；
2. 无 tag、但版本唯一（如 6.1 / 6.6 / 6.12 / 6.18）：匹配对应 KMI；
3. 无 tag 的共享 5.10 / 5.15：尝试按 SDK 消歧（SDK 33/34 → android13/14-5.15），仅在对应 `.ko` 已打包时采用；
4. 仍无法唯一确定：拒绝加载，不猜测。

补充：带 Android tag 但不配对时，也会按内核版本唯一候选兜底；SDK 31/32 → android12 也参与消歧，SDK 只是辅助信息。

优先使用 `/proc/version`，回退开机真实内核快照，最后才用 `osrelease`。

## dirty / 自编译内核

- 带 `-dirty` 不等于一定不兼容，但符号/CFI/KMI 差异风险高；
- 不要反复试错加载；失败会写 `load.log`；
- 确认不了 KMI 时用「强制指定 KMI」，并准备回滚。

处理方式：

1. **5.10 / 5.15 无 tag**：用 WebUI「强制指定 KMI」按系统 Android 版本选 `android12/13/14-5.10` 或

2. **6.1 / 6.6 / 6.12 / 6.18 定制内核**：版本唯一时自动匹配，无需指定；
3. **4.x / 5.4 内核**：模块不提供对应 `.ko`，不要尝试；
4. 报问题请附 `ctl.sh kmiinfo` 的输出（含 `suggest_kmi` 的建议值）与 `load.log`。

## 手动指定

WebUI 配置页填写「强制指定 KMI」，例如 `android14-5.15`，保存后点「加载并应用」。

## 诊断

```sh
su -c "sh /data/adb/modules/susfs_allinone/ctl.sh kmiinfo"
```

输出包含 osrelease、matched、packaged、guessed、内核配置等。常见失败原因见 [FAQ](FAQ.md)。
